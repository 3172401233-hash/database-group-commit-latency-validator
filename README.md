# database-group-commit-latency-validator
验证组提交批处理、持久化和复制延迟约束

## 概述

`group_commit.py` 模拟数据库组提交 (group commit): 领导者把多个事务合成
一批做一次 fsync, 再复制到远地副本。针对"领导者只在本地落盘就返回成功"
这一隐患, 模拟器区分两种时间并计算每个事务对客户端可见的**安全提交时间**:

- `leader_ack_time`: 领导者本地 fsync 完成即返回的时间 (不耐久)。
- `visible_time`: 批次在多数派节点持久化完成的时间 (故障切换后仍可恢复)。

两者之差即耐久性风险窗口: 若领导者在该窗口内宕机, 已"确认"的事务可能丢失。

## 耐久性前提

1. **本地持久化 ≠ 耐久**。只有多数派 (cluster_size // 2 + 1, 含领导者)
   确认后, 事务才对客户端可见; 在此之前返回成功属于提前确认 (premature ack)。
2. **批次不能无限推迟**。批次满 `batch_max_size` 立即关闭; 否则最多等待
   `batch_max_wait` 强制关闭, 小事务不为凑批被无限延迟。
3. **领导者切换必须重新判定**。切换时未达到多数派的批次不默认成功:
   - 旧领导者尚未落盘 -> 批次在新领导者上重排 (REBASED), 重新 fsync;
   - 新领导者持有该批次 -> 重新 fsync + 复制, 重算可见时间 (RECOVERED);
   - 仅旧领导者持有 -> 批次丢失 (LOST), 事务可见时间为空, 需客户端重发。
4. **已达多数派的批次不受切换影响** (SAFE)。
5. 多数派按原集群规模计算, 切换后存活节点不足多数派时批次无法提交。

## 运行

```sh
python group_commit.py    # 运行内置演示场景, 输出每事务报告
python -m unittest        # 运行测试 (批次交叉 / 慢副本 / leader 切换 / deadline)
```

输出列: `leader_ack` 本地落盘返回时间, `visible` 安全可见时间 (LOST 表示
丢失), `wait` 批次内等待, `risk` 耐久性风险等级, `deadline_missed` 是否
错过客户端 deadline。

兼容 Python 3.8.2+ (仅使用标准库, 无 3.9+ 语法)。
